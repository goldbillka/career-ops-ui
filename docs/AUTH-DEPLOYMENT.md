# Single-tenant authentication and deployment

The default `HOST=127.0.0.1` stays unauthenticated for the trusted local workflow. On a non-loopback bind, the server fails closed (`503`) unless `WEB_UI_AUTH_TOKEN` is set to 32–2048 printable ASCII characters. Setting the token on loopback opts into the same gate, useful behind a TLS reverse proxy. Generate a fresh random value with `openssl rand -hex 32`; supply it through your service manager's secret environment, never through a checked-in file, static asset, URL, query string or shell command-line argument. Restart the process to rotate the token. Do not place it in frontend JavaScript.

The browser receives an HTTP Basic challenge on first visit: username **`career-ops`**, password **the configured token**. The browser's same-origin credentials cover the SPA, `fetch` requests, native `EventSource` GET streams and POST streams. API clients may instead send `Authorization: Bearer <token>` in a request header. Missing/wrong credentials receive `401` before body parsing or route execution; `/api/health` is private. Only `GET`/`HEAD /api/ping` remains public and reports `{ok, version}`. The app does not implement user accounts, separate permissions, a logout endpoint or multi-tenancy. Browser Basic credentials may remain cached until the browser session ends; use a separate browser profile and rotate the token if compromised.

## TLS and proxy prerequisites

**Do not expose the Node HTTP listener directly to a LAN or the internet.** Basic and Bearer credentials are reusable secrets; HTTP would reveal them to a network observer. Terminate TLS at a trusted proxy with a valid certificate and redirect/refuse plaintext HTTP. Recommended topology: `HOST=127.0.0.1` with `WEB_UI_AUTH_TOKEN` supplied by a service manager, proxy on the same host forwarding to `127.0.0.1:4317` (not to a public Node listener). If the proxy is on a different host, use a protected private transport between it and Node as well; do not treat a public non-loopback HTTP hop as secure. Restrict direct access to Node by firewall. Preserve the `Authorization` header and the original `Host` header; do not log either credentials or sensitive API response bodies at the proxy. Permit long-lived streaming responses and disable proxy buffering for SSE. Disable shared caching of authenticated responses; the app emits `private, no-store` on authenticated responses.

Set `ALLOWED_HOSTS` to the exact public hostname if the proxy forwards it; never use `*` in a network deployment. A forwarded non-loopback Host requires authentication even when Node listens on loopback, but a proxy that rewrites Host to `localhost` hides that signal: **always set `WEB_UI_AUTH_TOKEN` explicitly behind a public proxy**. The existing Host/Origin/Fetch-Metadata CSRF guard remains ahead of authentication. Configure `TRUST_PROXY` only to the actual proxy hop count if needed for IP rate limits; never trust arbitrary forwarded headers. The proxy must not bypass authentication for static assets or `/api/*` paths. A proxy-side auth layer is optional defense in depth, not a substitute for the app's gate.

## Verification before exposure

Run `node --test tests/auth-gate.test.mjs` and `node --test tests/playwright-auth-gate.mjs` with Chromium/Playwright installed; also run `npm run test:ci`. From a trusted test network behind TLS, check unauthenticated SPA, `/api/cv`, `/api/config`, `/api/health`, SSE and a mutation all return 401; with browser Basic credentials, verify the dashboard, CV fetch and stream work; confirm `/api/ping` exposes only liveness. Then verify the proxy denies plaintext HTTP and direct Node access, enforces the exact hostname and does not log credentials. Do not enable LAN/public exposure until those checks pass in the actual deployment topology.
